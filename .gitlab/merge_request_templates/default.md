## Чеклист перед слиянием

- [ ] Тип изменения указан в заголовке Merge Request.
  Допустимые типы: `feat` — новая функциональность; `fix` — исправление бага; `refactor` — рефакторинг; `test` — тесты; `docs` — документация; `chore` — служебные изменения; `perf` — оптимизация производительности; `ci` — изменения в CI/CD; `revert` — откат изменений.
- [ ] Заголовок Merge Request на русском.
  Пример: `feat(api): добавил эндпоинт получения пользователей`.
- [ ] Проверки пройдены: `make project-check`.

## Рекомендации по формулировке заголовков для Merge Request

- **Язык** — используй русский язык согласованно.
- **Глаголы** — всегда в прошедшем времени: «добавил», «исправил», «вынес», «обновил».
- **Конкретика** — будь точен: «исправил обработку null в user_service» вместо «исправил ошибку».

### Примеры хороших заголовков для Merge Request

- `feat(auth): реализован вход через OAuth2`
- `fix(db): исправлено закрытие соединения с БД`
- `refactor(users): вынес логику валидации в отдельный модуль`
