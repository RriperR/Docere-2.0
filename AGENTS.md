# Docere: руководство для агента

## Сначала определи область задачи

- `README.md` — продукт, локальный запуск и демонстрационный сценарий.
- `ARCHITECTURE.md` — источник истины для слоёв, бизнес-инвариантов и принятых компромиссов. Читай только относящийся к задаче раздел.
- `CONTRIBUTING.md` — процесс разработки, документация и требования к MR.
- `docs/archive` — исторические PRD, журнал и завершённый task plan; не используй их как актуальные инструкции.

Не загружай все документы целиком без необходимости. Сначала ищи нужный символ или заголовок через `rg`, затем открывай небольшой релевантный диапазон.

## Структура

- `src/app/domain` — сущности, enum и чистые бизнес-правила.
- `src/app/application` — use cases, ports и DTO.
- `src/app/infrastructure` — SQLAlchemy, S3, JWT, ZIP/DICOM, Celery и реализации ports.
- `src/app/presentation` — FastAPI, Pydantic-схемы, DI, HTTP и CLI.
- `tests/critical` — основные продуктовые, security- и архитектурные регрессии.
- `frontend/src` — React + TypeScript; публичные API-типы повторяют response schemas, но не импортируют backend internals.
- `migrations/versions` — миграции Alembic; существующие миграции после применения не переписывай.

## Архитектурные правила

- Соблюдай направление зависимостей: `presentation -> application -> domain`; `infrastructure` реализует application ports. `domain` не знает о внешних слоях.
- Не помещай бизнес-правила, ORM-запросы и SQLAlchemy rows в routers. Pydantic-схемы не являются доменными моделями.
- Новую возможность проводи по цепочке: domain invariant → application DTO/use case/port → infrastructure adapter → presentation mapping → frontend workflow.
- Сохраняй provenance доступа, подтверждений и импорта. Отзыв sharing не должен удалять независимый источник доступа.
- Импорт архива остаётся review workflow: эвристики не должны незаметно изменять медицинскую историю.
- Следуй существующему transaction boundary: router выполняет commit/rollback, use case определяет смысл операции.
- Известные компромиссы перечислены в `ARCHITECTURE.md` §20; не расширяй их молча.

## Реализация

- Python 3.12+ (runtime и CI используют 3.13), строгий `mypy`, одинарные кавычки, длина строки 120.
- Публичные Python-модули, классы и функции документируй по-русски; docstring — Google style с `Args`, `Returns`, `Raises` при наличии.
- Предпочитай точечное изменение существующего паттерна новой абстракции или зависимости.
- При изменении поведения обновляй соответствующий раздел `README.md` или `ARCHITECTURE.md`; не переписывай документацию ради косметики.
- Не добавляй секреты и реальные медицинские данные. `seed-demo` очищает прикладные таблицы и допустим только в локальном/демо-окружении.

## Проверка с быстрым feedback loop

Сначала запускай минимальную проверку затронутой области:

```bash
make test ARGS='tests/critical/test_<area>.py -q'
uv run ruff check <changed-paths>
uv run ruff format --check <changed-paths>
```

Затем выбери gate по области изменения:

- backend/domain/application/infrastructure/presentation: `make test-critical`, затем при существенном изменении `make project-check`;
- архитектурная граница: `make test ARGS='tests/critical/test_architecture_layers.py -q'`;
- frontend: `cd frontend && npm run build && npm run lint`;
- миграция: проверь upgrade и, когда безопасно для локальной БД, downgrade/повторный upgrade.

Не утверждай, что проверка прошла, если команда не запускалась. Если полный gate невозможен из-за отсутствующего сервиса или зависимости, запусти доступные точечные проверки и явно назови остаточный риск.

## Готовность результата

- Изменение соответствует запросу и существующим бизнес-инвариантам.
- Есть тест на новое или исправленное поведение, если изменение не чисто документальное.
- Выполнены релевантные проверки выше.
- Diff просмотрен на случайные изменения, утечки секретов, нарушение access control и несовместимость API/БД.

## Git

- После каждого завершённого логического изменения делай локальный commit.
- Используй формат `type(scope): описание` из `CONTRIBUTING.md`; не смешивай несвязанные изменения.
- Не выполняй push без явного запроса пользователя.
