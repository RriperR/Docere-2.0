# Docere

**Рабочее пространство для врачей: медицинские документы, совместный разбор и сохранённый результат.**

Docere помогает собрать историю пациента из документов разных источников, выбрать материалы
для обсуждения с коллегами и зафиксировать итог. Врач сохраняет контроль над тем, кому доступны
записи и какие сведения из импорта попадут в медицинскую историю.

[Посмотреть интерфейс](docs/PRODUCT-TOUR.md) · [Запустить демо](docs/DEMO.md) · [Документация](docs/README.md)

![Рабочее место врача](docs/screenshots/current/dashboard.png)

## Основной сценарий

1. **Загрузить документы.** Один ZIP или несколько PDF/PNG/JPEG; DICOM группируется по исследованию.
2. **Проверить записи.** Выбрать документ, сверить оригинал с полями, указать пациента и дату.
   AI может предложить значения со ссылками на источники; применение и исправление выполняет врач.
3. **Пригласить коллегу.** В клинический случай включаются выбранные записи одного пациента.
   Участник принимает приглашение, изучает материалы и отвечает на адресованный запрос.
4. **Зафиксировать результат.** Координатор сохраняет версию итога и завершает разбор.
   Отдельное действие публикует итог в истории с выбранной датой медицинского события.

[Экскурсия](docs/PRODUCT-TOUR.md) показывает этот путь и дополнительные возможности на актуальных экранах.

## Возможности

| Область | Что можно сделать |
|---|---|
| История пациента | Просматривать хронологию, создавать записи, открывать вложения и комментарии |
| Проверяемый импорт | Исправлять даты, распределять документы между пациентами, проверять возможные дубли |
| Совместная работа | Приглашать врачей, обсуждать материалы, запрашивать мнение, сохранять версии итога |
| Управляемый доступ | Передавать отдельные записи, принимать или отклонять доступ, отзывать его |
| AI-помощь | Извлекать поля документа и готовить личную сводку выбранных материалов со ссылками на источники |
| Входящие | Находить приглашения, запросы мнения, доступы и документы на проверке в одной очереди |
| Оформление | Использовать светлую, тёмную или системную тему; настройка в меню аккаунта справа сверху |
| Роли и аудит | Подавать и рассматривать заявки врачей, управлять пользователями, просматривать значимые действия |

Членство в случае не открывает всю карту пациента. При потере доступа хотя бы к одному материалу
клинический контекст случая скрывается. Независимые основания доступа сохраняются при отзыве
другого основания. Создание или публикация записи не присваивает подтверждённый статус автоматически.

## Попробовать локально

Нужны Docker с Compose, Node.js 22.12+ и npm. Из корня репозитория:

```sh
cd frontend
npm ci
npx playwright install chromium
cd ..
sh scripts/product_demo_stand.sh up
```

Для **нового** стенда один раз создайте администратора, затем подготовьте синтетический набор:

```sh
sh scripts/product_demo_stand.sh create-admin
PRODUCT_DEMO_WEB_URL=http://localhost:8012 node scripts/product_demo_setup.mjs
```

Откройте [localhost:8012](http://localhost:8012). Скрипт напечатает путь к `OPEN-ME.md`
со ссылками и логинами двух врачей. Повторный setup добавляет новый набор, сохраняя прежние данные.
На уже подготовленном стенде используйте существующий `OPEN-ME.md`; `create-admin` повторять не нужно.

Подробная подготовка, включение AI и обновление этого стенда: [DEMO.md](docs/DEMO.md).
Обычное окружение разработки на порту 8000: [DEVELOPMENT.md](docs/DEVELOPMENT.md).
Старые команды `make demo-up` и `make demo-reset` очищают прикладные таблицы; не используйте их для обновления данных.

## Технологии и разработка

Python, FastAPI, SQLAlchemy, PostgreSQL, Alembic; Celery/Redis и PostgreSQL outbox;
S3-совместимое хранилище MinIO; React, TypeScript, Vite, Zustand и Tailwind CSS.
Направление зависимостей: presentation → application → domain; infrastructure реализует
прикладные ports. Подробности — в [архитектуре](ARCHITECTURE.md).

```sh
make project-check       # backend
make frontend-check      # TypeScript, build, lint, Vitest
```

Для backend-команд нужны Python 3.12–3.13 и `uv sync --all-groups`.
E2E запускаются на отдельном синтетическом наборе: [проверки](docs/VALIDATION.md).

## Границы текущей версии

AI использует настроенный внешний OpenAI-совместимый API и требует проверки оригиналов врачом.
AI предлагает извлечённые факты; медицинские выводы и дальнейшие действия определяет врач.
Записи сохраняются только после решения пользователя.
DICOM доступен как вложение; полноценного DICOM-viewer, интеграции с МИС, видеосвязи и поиска
по тексту сканов в этой версии нет. Проверки на синтетических данных не заменяют проверку
полезности с реальными врачами: [протокол исследования](docs/PRODUCT-VALIDATION.md).
