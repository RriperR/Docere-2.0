# Подготовка демонстрационного стенда Docere

Для знакомства со всем продуктом: [наглядная экскурсия с настоящими скриншотами](PRODUCT-TOUR.md).

[Сценарий выступающего: действия, реплики и тексты для копирования](DEMO-PRESENTER.md).

Показываем один результат: документы пациента превращаются в проверенную хронологию,
адресный вопрос коллеге и сохраняемый итог со ссылками на источники. Все материалы,
имена и клинические тексты вымышлены. Это демонстрация рабочего процесса, не медицинское заключение.

## Запуск и вход

Сначала установите frontend dependencies (`cd frontend && npm ci && npx playwright install chromium`).
Далее из корня репозитория с работающим Docker:

```sh
sh scripts/product_demo_stand.sh check
# Только если API отсутствует: sh scripts/product_demo_stand.sh up
# Один раз для нового стенда: sh scripts/product_demo_stand.sh create-admin
sh scripts/product_demo_stand.sh dev
```

В другом терминале:

```sh
node scripts/product_demo_setup.mjs
```

Скрипт напечатает путь к `artifacts/product-demo/<run>/OPEN-ME.md` и `state.json`.
Откройте OPEN-ME: там готовые ссылки и логины двух врачей. Пароль синтетических
аккаунтов — `ProductDemo123`. UI: `http://127.0.0.1:4174/auth/login`;
API: `http://localhost:8012/api`. Для просмотра готовой Docker-сборки: порт 8012.
Dev UI на 4174 показывает текущие изменения исходников.

`check/up` используют отдельный Compose project `docere-roadmap-a2-20261013`,
его собственные volumes и порт 8012; обычный `up` не загружает `.env` и отключает AI.
Для включения настроенного провайдера после сборки выполните:

```sh
sh scripts/product_demo_stand.sh ai-up
```

Команда читает только `APP_IMPORT_AI__*` из локального `.env` (нужна `.venv` с python-dotenv),
включает AI у API, worker и dispatcher и запускает зависимости. URL, модель и токен обязательны;
секреты не выводятся и не включаются в Git. Остальные настройки `.env` не используются.
Повторный обычный `up` при остановленном API возвращает режим без AI — после него повторите `ai-up`.
Само включение не запускает анализ; выбирайте синтетические файлы и запускайте его явно в UI.
`up` переиспользует уже отвечающий API; сначала проверьте имя проекта в `check`.
Если порт занят другим проектом, выберите свободный порт в отдельной копии override.
`create-admin` повторно не запускают: существующий email не заменяется.
Дополнительные настройки setup: `PRODUCT_DEMO_API_URL`, `PRODUCT_DEMO_WEB_URL`,
`PRODUCT_DEMO_ADMIN_EMAIL`, `PRODUCT_DEMO_ADMIN_PASSWORD`, `PRODUCT_DEMO_OUTPUT`.
В setup не передавайте реальные данные или рабочие пароли.
`PRODUCT_DEMO_OUTPUT`, если задан, должен указывать на ещё не существующий каталог.

Каждый запуск setup создаёт новые аккаунты, пациента и файлы; прежние данные сохраняются.
Скрипт использует регистрацию, одобрение роли администратором, импорт, ручной resolve,
приглашение врача, запрос мнения, ответ, итог и публикацию через публичный API.
PNG создаются локально браузером из содержательных HTML-документов. AI не вызывается.

## Подготовленные состояния

В одном наборе есть: три исходных документа; реальный завершённый импорт;
отдельный импорт на ручной проверке; черновик случая; активный запрос к кардиологу;
завершённый случай с ответом и опубликованным итогом. Третий аккаунт `empty`
в state.json — врач с пустым рабочим столом для проверки первого входа.

Перед показом откройте два независимых профиля браузера: координатор и коллега.
В профиле координатора заранее откройте историю пациента и готовый итог;
в профиле коллеги — активный случай из OPEN-ME. Подготовленные тексты доступны
в `state.json → texts`; их можно скопировать для сокращения набора.

## Что показывать

Маршрут и реплики находятся только в [DEMO-PRESENTER.md](DEMO-PRESENTER.md),
все возможности со скриншотами — в [PRODUCT-TOUR.md](PRODUCT-TOUR.md).
Для живого ответа, завершения и публикации используйте новый run: эти действия меняют состояние.
Заранее подготовленный итог показывайте как готовый пример, не как результат текущего нажатия.

## Проверка и ограничение AI

Перед показом выполните проверку без изменения данных:

```sh
node scripts/product_demo_check.mjs /absolute/path/to/run/state.json
```

```sh
cd frontend
PRODUCT_DEMO_STATE=/absolute/path/to/a/new/run/state.json \
PLAYWRIGHT_BASE_URL=http://127.0.0.1:4174 \
npx playwright test e2e/product-demo.spec.ts --workers=1 --retries=0
```

Тест расходует открытый вопрос активного случая: отвечает как коллега и сохраняет итог.
Для показа используйте другой свежий run. Без state тест явно skipped.

AI-импорт можно показать после `ai-up`: выберите файл на экране проверки, запустите анализ,
откройте источник предложения и примените отдельное поле. Не показывайте подготовленные
человеческие тексты как результат модели. Успех одного документа подтверждает подключение,
но не качество извлечения на всех документах: экспертная оценка E2 остаётся отдельной работой.

## Обновить frontend на существующем стенде 8012

Из корня репозитория:

```sh
docker compose --env-file /dev/null -p docere-roadmap-a2-20261013 \
  -f docker-compose.yml -f scripts/product_demo.compose.yaml build frontend
docker compose --env-file /dev/null -p docere-roadmap-a2-20261013 \
  -f docker-compose.yml -f scripts/product_demo.compose.yaml up -d --no-deps frontend
```

Если переопределён `PRODUCT_DEMO_PROJECT`, используйте своё имя вместо имени выше.
Эти команды обновляют только UI и сохраняют настройки API/AI и данные. Для обновления backend
сначала соберите тот же набор Compose-файлов, остановите прикладные процессы, выполните миграции
и запустите их; при включённом AI используйте также `scripts/product_demo_ai.compose.yaml` и
настройки `APP_IMPORT_AI__*`. Не запускайте базовый override на API, если хотите сохранить AI.
