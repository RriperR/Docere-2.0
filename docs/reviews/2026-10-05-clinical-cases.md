# Ревью совместного разбора клинических случаев — 5 октября 2026

Проверена реализация клинических случаев в `master` на `539b604` и связанные проверки доступа,
уведомления, SSE и React-интерфейс. Исправления находятся в ветке `refactor/clinical-cases-review`.

## Найденные проблемы и исправления

| Проблема | Последствие | Исправление |
|---|---|---|
| Старые HTTP-ответы могли обновить уже изменившийся экран | Результаты поиска, списки и панели отображали устаревшие данные | Отмена предыдущего запроса и проверка его актуальности перед изменением состояния |
| Ответ счётчика уведомлений мог прийти после выхода или нового запроса | В состоянии интерфейса восстанавливался старый счётчик | Поколение запросов в store; сброс делает предыдущие ответы недействительными |
| Состояние выбранного документа сохранялось при переходе между случаями | На новом экране оставалась панель документа предыдущего случая | Рабочее пространство привязано к ID случая; потеря доступа очищает выбор |
| Лимит SSE применялся к общей порции полученных байтов | Несколько допустимых событий в одном сетевом чтении ошибочно отклонялись | Лимит проверяется отдельно для каждого кадра, включая незавершённый |
| Проверка ACL загружала медицинские записи с комментариями и вложениями | Лишние запросы и объекты при чтении карточек и повторных проверках SSE | Проверка доступа ко всем ID материалов одним SQL-запросом без загрузки клинического содержимого |
| Основной use case объединял управление, обсуждение, материалы и итоги | Большой модуль было трудно менять и проверять | Отдельные use cases по функциям, общий `CaseContext` для ACL и событий, без наследования и фасада совместимости |
| Два HTTP-обработчика обращались напрямую к repository use case | Presentation обходил прикладные сценарии | Операции перенесены в application; добавлена архитектурная проверка этой границы |
| Результаты application/API описывались словарями `dict[str, object]` | Контракт не проверял конкретные поля и типы | Типизированные DTO и Pydantic response schemas; явные присваивания полей ORM |
| Часть docstrings повторяла шаблонные формулировки | Документация не объясняла параметры, результат и условия ошибок | Уточнены описания публичных сценариев и DTO, сохранён русский Google style |
| Метаданные разрешали Python 3.14 при несовместимом lockfile | `uv` выбирал интерпретатор, для которого не устанавливался закреплённый `psycopg-binary` | Поддерживаемый диапазон 3.12–3.13; версии Python-пакетов сохранены |
| В закреплённом Axios была опубликованная уязвимость | Зависимость требовала обновления | Axios обновлён до 1.20.0; проверены сборка, тесты и пользовательский сценарий |

Гонки интерфейса исправлены отдельно от серверных ACL: они не заменяют проверки доступа в API.
Правила членства, доступ ко всем материалам, происхождение sharing и отзыв независимых прав не менялись.

## Организация кода

- `application/use_cases/clinical_cases/management.py` — создание, материалы и участники;
- `discussion.py` — сообщения, запросы мнения, журнал и позиции прочтения;
- `conclusions.py` — версии итога, закрытие и публикация;
- `materials.py` — поиск, карточки записей и доступ к вложениям;
- `context.py` — общие проверки доступа и фиксация изменений;
- `dtos.py` — прикладные контракты результатов;
- `application/ports/notifications.py` и `application/use_cases/notifications/` — порт и сценарии уведомлений;
- отдельные HTTP-модули и response schemas в `presentation/rest/public/v1/cases/`.

Транзакции остаются на существующей границе: HTTP-слой выполняет commit/rollback,
application определяет операции, infrastructure реализует порты. Подробности отражены в
[ARCHITECTURE.md](../../ARCHITECTURE.md), раздел 22.

## Оставшееся замечание по зависимостям

Полный `npm audit` сообщает о пяти пакетах с уровнем high в одной цепочке инструментов сборки:
`braces`, `micromatch`, `fast-glob`, `chokidar`, `tailwindcss`.
Для `braces` исправленная версия на момент проверки не опубликована:
[issue сопровождающего проекта](https://github.com/micromatch/braces/issues/70).
Здесь речь о рекурсивной обработке глубоко вложенного glob-шаблона.

В Docere шаблоны Tailwind заданы в конфигурации проекта; клинические данные не передаются в них.
Эта цепочка относится к dev-зависимостям сборки, а frontend-контейнер отдаёт готовую статику через Nginx.
Полный аудит поэтому пока не чистый. Обновление следует проверить после выхода исправления;
переход на другую основную версию Tailwind в это ревью не включён.

Обновление Axios основано на
[advisory сопровождающего проекта](https://github.com/axios/axios/security/advisories/GHSA-vh66-26gq-q6x8)
и [релизе 1.20.0](https://github.com/axios/axios/releases/tag/v1.20.0).
Это проверка зависимости; эксплуатация уязвимости в Docere не подтверждалась.
