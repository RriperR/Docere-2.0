## E1 — набор документов и эталон

Зависимость: нет; можно параллельно с B при непересекающихся файлах.

Расширить существующий генератор до минимум 20 синтетических документов:
текстовый PDF, скан, фото, поворот/низкое качество, несколько страниц/пакетов,
нет даты, равнозначные даты, дата рождения рядом с датой события, разные пациенты,
противоречивые сведения, внедрённые инструкции, нечитаемый/запароленный PDF.
Отдельно проверить mixed ZIP с DICOM: DICOM не отправляется в AI.

Для каждого документа хранить ожидаемые допустимые значения/пустые поля, факты,
страницы и подтверждающие фрагменты. Не требовать буквального совпадения всего пересказа.
Разделить development и holdout; не подгонять инструкцию на holdout.
В Git только синтетические исходники/генератор и эталоны, без ключей и сетевых ответов.
Результат — описание набора и команды генерации/оценки; существующие 5 примеров сохранить.

## E2 — измерения извлечения и источников

Зависимость: E1.

- Автоматически считать точность заполненных реквизитов, пропуски обязательных для
  конкретного документа фактов, ошибки формата/страниц, корректный отказ при неоднозначности.
- Для фактического пересказа сохранить таблицу утверждение → источник → ручная оценка
  «подтверждено / не подтверждено / противоречит». Другой LLM не считать истинным эталоном.
- Отдельно измерить время запроса, частичные ошибки, доступные usage.
  Стоимость показывать только при известном тарифе, иначе «нет данных».
- Реальные запуски требуют явного opt-in, синтетических данных и настроенного провайдера.
  Default CI использует управляемый adapter и не расходует внешние запросы.
- Отчёт включает model/prompt version, параметры, размер набора и неудачные примеры.
  Результаты характеризуют этот набор, не клиническую точность на любой документации.
- Найденные ошибки исправлять адресно с regression test; не скрывать проблемные примеры.

Приёмка: воспроизводимый machine-readable результат и краткий отчёт;
проверки отсутствующей даты, prompt injection, чужого доступа, неверных источников
и неоднозначных полей остаются обязательным gate.

## E3 — доработка объяснений AI и контроль обработки

Зависимость: E2.

Проверить существующее поведение и исправить только обнаруженные пробелы:
- Личная сводка и врачебный итог визуально различимы; самостоятельная запись не создаётся.
- Изменившийся источник делает старую сводку недоступной/требующей повторного анализа
  согласно текущему контракту; не показывать старый клинический текст после отзыва.
- Частичный результат явно перечисляет неанализированные документы/страницы.
- Ошибки провайдера понятны: недоступность, авторизация, лимит, таймаут; без raw response.
- Повторный анализ сохраняет ручные правки. Источник открывается на нужной странице.
- В существующей диагностике добавить технические latency/usage, если их ещё нет;
  D6 владеет общей панелью, E3 только AI DTO и отображением.
- Проверить 200% zoom и клавиатуру для AI-сводки — на baseline это отдельный незакрытый пункт.

Приёмка: адресные frontend/backend тесты, снимки 390/768/1440 и 200%;
отказ AI не запрещает обычный импорт/разбор.

## E4 — сводка истории вне случая (отложено)

Не реализовывать автоматически после E3. Условие старта: владелец подтвердил пользу
по E2/F2 и выбрал сценарий подготовки к приёму.

Перед реализацией нужен отдельный согласованный контракт: явный выбор записей одного пациента,
повторный ACL каждого источника, личный результат, фактическая хронология и источники,
политика устаревания, отсутствие доступа к невыбранным записям и автоматических рекомендаций.
Повторно использовать существующую подготовку страниц/AI jobs; не копировать case ACL
в другую предметную область без отдельной политики.
Результат текущего плана для E4 — запись в backlog, не новая функция.
